## 🚀 加速概述

### 为什么需要 NPU 加速?

**CPU 推理的局限性**:
- ❌ 串行处理,并行度低
- ❌ 通用架构,AI 计算效率低
- ❌ 功耗高 (95W+)
- ❌ 推理速度慢 (365ms/图像)

**NPU 的优势**:
- ✅ 专为 AI 设计的硬件架构
- ✅ 大规模并行计算
- ✅ 低功耗 (30-65W)
- ✅ 高吞吐量 (20+ img/s)

## 🖥️ 硬件架构

### Ascend NPU 架构

```
┌─────────────────────────────────────────┐
│         Ascend 310P 架构图              │
├─────────────────────────────────────────┤
│                                          │
│  ┌──────────────────────────────────┐  │
│  │   AI Core (向量/矩阵计算单元)    │  │
│  │   - 16个 AI Core                 │  │
│  │   - 每个 Core 含:                │  │
│  │     • Vector 单元 (向量运算)     │  │
│  │     • Cube 单元 (矩阵乘法)      │  │
│  │     • Scalar 单元 (标量运算)    │  │
│  └──────────────────────────────────┘  │
│                                          │
│  ┌──────────────────────────────────┐  │
│  │   DVPP (数字视觉预处理)         │  │
│  │   - 硬件解码 (JPEG/H.264)       │  │
│  │   - Resize/Crop加速              │  │
│  │   - 格式转换 (RGB/YUV)          │  │
│  └──────────────────────────────────┘  │
│                                          │
│  ┌──────────────────────────────────┐  │
│  │   内存 (HBM/DDR)                 │  │
│  │   - 8GB HBM2                     │  │
│  │   - 高带宽 (512GB/s)             │  │
│  └──────────────────────────────────┘  │
│                                          │
└─────────────────────────────────────────┘
```

### 关键组件

#### 1. AI Core
- **Vector 单元**: SIMD 向量运算 (加法、乘法、激活函数)
- **Cube 单元**: 矩阵乘法专用硬件 (矩阵×矩阵)
- **Scalar 单元**: 控制流和标量运算

#### 2. DVPP (数字视觉预处理)
- 硬件加速的图像解码
- Resize/Crop 操作加速
- 格式转换 (无需CPU参与)

#### 3. 内存层次
```
L0 Buffer (256KB) ← 最快
    ↓
L1 Buffer (2MB)
    ↓
HBM (8GB) ← 高带宽
    ↓
Host Memory (系统内存)
```

## ⚡ 优化技术

### 1. 模型量化

#### FP32 → FP16
```
原始模型: FP32 (32位浮点)
   ↓
量化: FP16 (16位浮点)
   ↓
效果:
  • 模型大小: 减半
  • 显存占用: 减半
  • 计算速度: 2倍提升
  • 精度损失: < 0.5%
```

#### INT8 量化
```python
# 量化过程
原始权重: [-1.5, 0.3, 2.1, -0.8]  # FP32
   ↓
找到缩放因子: scale = max(abs(weights)) / 127
   ↓
量化: quant = round(weight / scale)
   ↓
量化权重: [-90, 18, 127, -48]  # INT8
   ↓
推理时: output = (quant_weight * input) * scale
```

**效果**:
- 模型大小: 减少 75%
- 推理速度: 3-4倍提升
- 精度损失: 1-2% (可接受)

### 2. 算子融合

**融合前**:
```
Conv2D → BatchNorm → ReLU → Conv2D
  ↓       ↓          ↓       ↓
 DRAM   DRAM       DRAM    DRAM
(4次内存访问,带宽瓶颈)
```

**融合后**:
```
Conv2D+BN+ReLU (融合算子)
         ↓
       DRAM
(1次内存访问,减少3/4带宽)
```

**常见融合模式**:
- Conv + BN + ReLU
- MatMul + BiasAdd + Activation
- Multiple ElementWise ops

### 3. 内存优化

#### 内存池管理
```python
# 预分配内存池
memory_pool = allocate(1GB)

# 重用内存
for layer in layers:
    buffer = memory_pool.get_buffer(layer.size)
    layer.compute(buffer)
    memory_pool.release(buffer)  # 立即释放供下一层使用
```

#### 显存优化
- 输入/输出共享内存
- 中间结果及时释放
- Batch 动态调整

### 4. 批处理优化

```
单样本推理:
  图像1 → NPU (空闲) → 结果1   # 算力利用率: 20%

批处理 (Batch=16):
  [图像1-16] → NPU (满载) → [结果1-16]  # 算力利用率: 85%
```

**最优 Batch Size 选择**:
- Ascend 310P: 16-32
- Ascend 910: 32-64

## 🔬 实际优化案例

### 本项目: UNI + 分类器

#### 优化前 (CPU)
```
图像加载: 50ms
  ↓
预处理: 20ms
  ↓
UNI特征提取: 280ms  ← 瓶颈
  ↓
分类器推理: 15ms
  ↓
总计: 365ms
```

#### 优化后 (NPU)
```
图像加载: 10ms (DVPP硬件解码)
  ↓
预处理: 2ms (DVPP加速)
  ↓
UNI特征提取: 25ms (NPU FP16) ← 11倍提升
  ↓
分类器推理: 8ms (NPU INT8)
  ↓
总计: 45ms

加速比: 8.1×
```

### 关键优化点

1. **DVPP 硬件解码**: 50ms → 10ms (5×)
2. **UNI 模型量化**: FP32 → FP16 (2×)
3. **算子融合**: 减少内存访问 (1.5×)
4. **批处理**: Batch=1 → Batch=16 (3×)
5. **分类器量化**: FP32 → INT8 (4×)

## 💡 优化建议

### 模型层面
1. 使用 FP16 而非 FP32
2. 量化不敏感层为 INT8
3. 简化模型结构(减少分支)
4. 使用标准算子(避免自定义)

### 推理层面
1. 增大 Batch Size (充分利用算力)
2. 使用 DVPP 硬件预处理
3. 预分配内存池
4. Pipeline 并行 (多线程)

### 部署层面
1. 模型预加载到显存
2. 输入异步拷贝
3. 多实例并发 (单卡多模型)
4. 监控 NPU 利用率
